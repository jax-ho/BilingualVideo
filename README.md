# 放牛班的春天 iPad App

一个离线、原生 SwiftUI iPad App。家长通过“文件”App 管理严格配对的中英文 MP4，App 按自然日生成观看计划；儿童首页默认开放连续 3 组，有播放的日子向前推进一组，未播放的日子自动顺延。

## 使用入口

- 孩子从首页开始或继续观看；严格模式会显示接着看的视频和已播放时间，普通模式可分别选择中文、英文。
- 家长验证密码后进入全屏设置，按“视频资源 → 计划编辑 → 观看设置”管理内容、日期和播放规则。空视频库会直接展示导入步骤。
- 观看设置更改立即生效；计划编辑保留独立草稿，需要点击“保存”并确认预览。预览会说明是否重置今日进度，退出未保存草稿时才询问是否放弃。
- 日历中的编号表示当天的第一组。先选一组，再点目标日期，整条计划一起移动；分组按钮与目标日期不必同时出现在屏幕上。

界面跟随系统浅色、深色及字体大小，支持 iPad 横竖屏；大字体和较窄窗口中的长页面可以滚动操作。

## 观看设置

### 播放模式

提供“普通”和“严格”两种模式，默认“严格”。普通模式按计划显示当天可看的视频组，从点选的视频开始，按页面顺序自动连播：第一组中文 → 第一组英文 → 第二组中文 → 第二组英文，以此类推，不退出全屏。模式设置自动保存在本机，不改动已保存的计划；已有的手动设置会保留。

普通模式下可设置“循环播放”（默认开启）：关闭时，当天最后一组英文播完停止，可使用系统播放器手动重播；开启时，回到当天第一组中文继续播放，即使从中间的视频开始也会循环到当天第一组中文。只有一组时按中文 → 英文 → 中文循环。循环不会越过当天可看的组数；下一集资源缺失或损坏时停止并提示，不跳过或补位。切到后台会暂停，关闭播放器会结束连播。

### 每日观看组数

进入“家长入口”，验证 PIN 后选择“观看设置”，可调整每天可看的组数（最少 1 组，默认 3 组），自动保存并立即生效。每组包含中文和英文两个视频。普通模式可不限次数重播；严格模式若当天实际列表变化，会重置当天播放进度。

组数为 3 时，第一天开放计划中的第 1、2、3 组，当天有实际播放，第二天开放第 2、3、4 组；如果整天未播放，第二天仍开放第 1、2、3 组。顺序以保存的计划为准；计划末尾只显示剩余组数，不增加新的视频组。资源缺失的组会提示不可用，不会用窗口外的视频补位。修改组数不改变已保存计划的起始日期或顺序。

### 严格模式

在“家长入口 → 观看设置 → 播放模式”选择“严格”。首页只有“开始观看 / 继续观看”一个入口，顺序为第一组中文 → 第一组英文 → 下一组中文。不能选集、拖动进度或跳转，只允许暂停、继续和关闭；播放控制会自动隐藏，轻点画面可唤出。普通模式不受影响。

严格模式每秒保存一次进度，暂停、关闭和切到后台时立即保存；退出再进入或重启 App 后恢复到已保存的位置。只有视频自然播完才进入下一集，普通模式的循环开关不影响严格模式。当天最后一集结束后显示“今天的视频已经播放完毕”，当天不能重播；切换模式再切回来也不会清除这条记录。存储失败时停止播放并提示，不继续跳集。

播放进度以本地日期为单位。保存计划或修改组数后，若当天实际视频组、顺序或数量变化，就清除当天进度和已播完状态，从新列表第一组中文的开头重新播放。只修改未来安排、未保存的草稿、保存相同计划或修改组数但实际列表未变时，不会重置；临时缺失视频资源也不会清除进度。计划和进度重置一起保存，旧播放器的回调不能继续写入新计划。当天实际播放过的记录仍保留，不影响自动顺延的判断。

家长也可在“家长入口 → 观看设置”点击“重置今日进度”，确认后清空严格模式当天的进度和已播完状态，从今天第一集开头重新观看。取消不会修改进度；没有今日进度时按钮置灰。手动重置不会改变观看计划、播放设置或当天实际播放过的记录，存储失败时保留原进度并提示重试。

次日使用现有计划生成新的当天列表，不追加昨天未播完的集数。跨午夜会停止旧列表，返回首页重新进入当天播放。仍遵循“有实际播放就算当天看过”的顺延规则。

### 自动顺延

任何一个视频真正开始播放，就算当天播放过，不要求播完。点击卡片、加载文件、加载失败或仅停留在播放器都不算播放。普通模式的连播、重播和跨午夜持续播放同样计入实际发生播放的日期；严格模式跨午夜停止旧列表，不将它计入新一天。

日期变化时结算已经结束的日子：漏看当天及后续安排自动顺延，过去已经发生的安排不变，日历和保存预览显示顺延后的实际日期。连续多天没打开 App，会在下次打开时补算，不依赖后台一直运行；反复打开不会重复顺延。计划开始前的日子不计入，已结束的计划不会重新激活。

旧计划从升级后首次打开当天开始记录，不推测更早的观看情况。观看记录和顺延后的计划一起原子保存到本机。若计划编辑期间跨日，请重新查看最新安排再保存，避免用旧草稿覆盖自动顺延的结果。

## 从 GitHub 免费安装到 iPad

前提：一台 Mac、Xcode，以及运行 iPadOS 17.0 或更高版本的 iPad。普通 Apple Account 可以用于真机测试，不需要购买 Apple Developer Program。

1. 克隆项目并打开工程：

   ```sh
   git clone https://github.com/jax-ho/BilingualVideo.git
   cd BilingualVideo
   open BilingualVideo.xcodeproj
   ```

2. 在 Xcode → Settings → Apple Accounts 中登录自己的 Apple Account。免费账号会显示为“姓名 (Personal Team)”。

3. 用数据线连接并解锁 iPad；如果询问是否信任此电脑，请轻点“信任”。

4. 在 Xcode 左侧选择项目 `BilingualVideo`，再选择 TARGETS 下的 `BilingualVideo`，打开 Signing & Capabilities：

   - 保持 `Automatically manage signing` 开启。
   - Team 选择自己的 Personal Team。
   - 将 Bundle Identifier `com.jax.BilingualVideo` 改为自己的唯一标识，例如 `com.yourname.BilingualVideo`。

5. 在 Xcode 顶部选择 `BilingualVideo` scheme 和已连接的 iPad，点击 Run（▶）或按 `Command-R`。

6. 如果提示开启 Developer Mode，在 iPad 上打开“设置”→“隐私与安全性”→“开发者模式”，按提示重启并确认，然后回到 Xcode 再运行一次。

7. 首次启动后，到“文件”App →“我的 iPad”→“放牛班的春天”，把 MP4 分别放入 `Chinese/` 和 `English/`。

8. 回到 App，从“家长入口”创建 PIN、检查资源、生成并保存计划。

### 免费账号限制

Personal Team 仅适合在自己的设备上测试，不能用于 App Store、TestFlight 或长期分发 IPA。免费描述文件签发后 7 天到期，届时需要重新连接 iPad，在同一工程中再次 Run。

请保持同一个 Apple Account、Team 和 Bundle Identifier，并直接覆盖安装。不要先删除 App，否则 App 内的本地视频和计划也会被删除。

### 常见签名问题

- `Signing ... requires a development team`：在主 Target 的 Signing & Capabilities 中选择自己的 Personal Team。
- `Bundle Identifier is unavailable`：将 `com.jax.BilingualVideo` 改成自己的唯一 Bundle Identifier。
- `No profiles for ... were found`：确认 Apple Account 已登录、自动签名已开启、iPad 已解锁并信任 Mac、网络可用，然后重新 Run。
- `Developer Mode disabled`：在 iPad 的“设置”→“隐私与安全性”中开启开发者模式，重启并确认。
- iPad 没有出现在设备列表：重新连接并信任 Mac；确认 iPadOS 不低于 17.0，且 Xcode 已安装对应的平台支持。

工程已包含生成后的 `.xcodeproj`，安装 App 不需要运行 XcodeGen。修改 `project.yml` 后才需要运行 `xcodegen generate`；重新生成工程会覆盖直接在 Xcode 中修改的 Team 和 Bundle Identifier，因此应先同步修改 `project.yml`。

## 文件命名

- 文件名必须是纯数字加 `.mp4`，扩展名大小写均可。
- 同一数字编号的中英文文件组成一组；两边可使用不同的前导零，例如 `Chinese/005.mp4` 与 `English/5.mp4`。
- 同一目录中的 `5.mp4` 与 `005.mp4` 会被判定为重复编号。

## 测试

在 Xcode 中运行 `BilingualVideo` scheme 的测试，或使用：

```sh
xcodebuild -project BilingualVideo.xcodeproj \
  -scheme BilingualVideo \
  -destination 'platform=iOS Simulator,name=iPad Pro 13-inch (M5)' \
  test
```

命令行测试需要先在 Xcode → Settings → Components 安装 iOS Simulator runtime。可用 `xcodebuild -project BilingualVideo.xcodeproj -scheme BilingualVideo -showdestinations` 查看本机设备；若名称不同，请替换上面的 destination。

App 支持 iPad 四个屏幕方向，首页、播放器和家长设置均可横竖屏切换。严格模式旋转时保留当前集数、暂停状态和播放位置。计划编辑页的月历采用完整网格布局，避免横屏下列表反复估算日历行高。

若模拟器外壳转了，但 App 和 iPad 系统主屏幕都仍侧躺，先检查系统方向锁定；仍异常时可用 Simulator 的 Device → Restart 重启当前模拟设备，无需清除内容或重新导入视频。应分别验证“系统主屏幕能旋转”和“App 内容重新排成横屏”，不能只看模拟器窗口的宽高。

生成独立的正常和异常 Mock 视频目录：

```sh
./Tools/generate_mock_videos.sh
```

默认输出到带时间戳的新目录；也可传入一个不存在或为空的目标目录。脚本会拒绝写入非空目录，避免旧文件污染测试场景。脚本依赖开发机上的 `ffmpeg`，不会被打包进 App。

## 真机验收

发布前请在启用设备密码的 iPad 上完成以下检查：

- “文件”App 能看到 `Chinese/`、`English/`，添加或删除视频后资源页能准确刷新。
- 首次设置 PIN、错误 PIN、忘记 PIN 后的 Face ID/Touch ID/设备密码重设都符合预期。
- 中英文视频可播放、关闭、从头重播；文件损坏或播放期间被移除时只显示错误，不自动补位。
- 横竖屏、后台返回、跨午夜后，普通模式下“今日观看”仍对应本地自然日的连续视频组，组数以观看设置为准。
- 严格模式只有一个入口，暂停有效、拖动画面不跳进度；关闭重进、后台返回、重启后继续原进度。
- 严格播放器暂停后左右横屏、竖屏往返，位置保持不变；家长计划编辑页横屏打开、日历调整和保存均正常。
- 严格模式最后一集自然播完后显示“今天的视频已经播放完毕”，重启后仍不能重播；次日按计划解锁新列表。
